# Claude Code Guidelines

This document helps Claude Code work effectively with this Raspberry Pi kiosk dashboard project.

## Project Overview

A Raspberry Pi-based kiosk running a Chromium browser in fullscreen mode to display a Home Assistant dashboard for family chore management.

**What's Working:**
- `kiosk/kiosk.sh` - Launches Chromium in kiosk mode on boot
- `touchscreen/touchscreen-check.sh` - Automatic touchscreen recovery via soft reboot
- `mqtt/mqtt_listener.py` - MQTT subscriber for Home Assistant display control
- `mqtt/ha_init.py` - Publishes MQTT auto-discovery config to Home Assistant
- `display/display_control.py` - HDMI display power control
- `config.json` - Centralized configuration (generated by bootstrap, git-ignored)
- `config.json.template` - Configuration template with `__TOKEN__` placeholders
- `lib/config.sh` - Bash config loader (jq-based)
- `lib/config.py` - Python config loader (dot-notation access)
- `setup/bootstrap.sh` - Automated provisioning script
- `setup/verify.sh` - Post-setup verification script
- Git version control with clear commit history

## Key Commands

### Setup & Provisioning
```bash
# Run after cloning to a fresh Pi
./setup/bootstrap.sh

# Verify everything is configured correctly
./setup/verify.sh
```

### Kiosk Control
```bash
# Test kiosk mode manually
./kiosk/kiosk.sh

# Stop kiosk mode (via SSH)
pkill chromium
```

### Touchscreen Service Management
```bash
# Check service status
systemctl status touchscreen-check.service

# View logs
journalctl -u touchscreen-check.service -f

# Disable/enable service
sudo systemctl disable touchscreen-check.service
sudo systemctl enable touchscreen-check.service

# Manual test (not recommended - will reboot if touchscreen missing)
./touchscreen/touchscreen-check.sh
```

**How It Works:**
- Runs once at boot after configurable hardware stabilization wait
- Detects touchscreen via USB ID from config.json
- Uses flag file for boot loop protection
- Flag persists across soft reboots but cleared on power cycles
- Performs ONE automatic reboot if touchscreen missing, then stops

### MQTT Display Control
```bash
# Check MQTT listener service status
systemctl status mqtt-listener.service

# View MQTT listener logs
journalctl -u mqtt-listener.service -f

# Start/stop/restart service
sudo systemctl start mqtt-listener.service
sudo systemctl stop mqtt-listener.service
sudo systemctl restart mqtt-listener.service

# Manual display control (bypassing MQTT)
python3 display/display_control.py on
python3 display/display_control.py off
python3 display/display_control.py status
```

**MQTT Topics:**
- Command: `dashboard/display/command` (accepts: `on`, `off`, `status`)
- Status: `dashboard/display/status` (publishes: `on`, `off`, `unknown`)
- Availability: `dashboard/display/availability` (publishes: `online`, `offline`)

**How It Works:**
- `mqtt_listener.py` runs as a systemd service
- Connects to MQTT broker configured in `config.json`
- Subscribes to command topic and listens for messages from Home Assistant
- Executes `display_control.py` when commands received
- Publishes status updates back to Home Assistant
- Handles reconnection automatically on network issues
- Uses MQTT Last Will and Testament for availability tracking

## Configuration

All configurable values live in `config.json` (generated by `setup/bootstrap.sh` from `config.json.template`).

### Config Access in Scripts

**Bash scripts** source `lib/config.sh`:
```bash
source "$(dirname "${BASH_SOURCE[0]}")/../lib/config.sh"
url="$(cfg_get '.dashboard.url')"
broker="$(cfg_require '.mqtt.broker')"
```

**Python scripts** import `lib/config.py`:
```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent.parent / "lib"))
from config import get, require

url = get("dashboard.url")
broker = require("mqtt.broker")
```

## Coding Conventions

### Shell Scripts
- Use `bash` with `set -euo pipefail`
- Two-space indentation
- Quote all variables
- Keep functions small with descriptive verb names
- Lowercase filenames with hyphens (`bootstrap.sh`, `touchscreen-check.sh`)

### Python Scripts
- Type hints where applicable
- Descriptive function and variable names
- Standard library preferred over external dependencies

### Configuration
- All configurable values go in `config.json.template` with `__TOKEN__` placeholders
- Scripts read values via `lib/config.sh` (bash) or `lib/config.py` (python)
- Never hardcode values that differ between environments

## Testing & Verification

- `setup/verify.sh` is the central smoke test
- Extend it when adding new dependencies
- Document manual verification steps for hardware features (touchscreen, GPIO, display power)

## Git Workflow

### Commit Messages
- Present tense, concise subject lines under 70 characters
- Example: `sync autostart template`
- Group logical changes per commit
- Describe observable behavior in commit body when needed

### What to Track
- Configuration templates and libraries
- Scripts and automation
- Documentation

### What NOT to Track (see .gitignore)
- `config.json` (contains secrets, generated by bootstrap)
- Python cache (`__pycache__/`, `*.pyc`)
- Editor files (`*.swp`, `.vscode/`, `.idea/`)
- OS artifacts (`.DS_Store`)

## Important Notes

### Security
- Never hard-code secrets, IPs, or dashboard URLs beyond documented placeholders
- All secrets live in `config.json` which is git-ignored
- `config.json.template` uses `__TOKEN__` placeholder tokens
- Bootstrap script prompts for values and generates `config.json`

### Future Features Planned
- Additional Home Assistant automations as needed
- Potential GPIO sensor integration

### Bootstrap Recovery
- Re-run `setup/bootstrap.sh` after OS updates or Pi rebuilds
- Ensures permissions, systemd services, and autostart files remain current
- Designed for quick recovery from failures
