Modify the existing kiosk/kiosk.sh to add three capabilities:

**1. Touch-friendly Chromium flags (BRW-01):**
Add these flags to the chromium-browser launch command:
- `--disable-touch-drag-drop` (prevents drag-drop interpretation of touch)
- `--overscroll-history-navigation=0` (prevents swipe-back/forward gesture)
- `--disable-pinch` (prevents accidental zoom on touch)

Per BRW-01 requirement: "try Chromium flags first, explore alternative browser only if flags fail on hardware." This is the flags-first approach.

**2. Chromium Preferences cleanup before launch (BRW-05):**
Before the chromium-browser launch, add a sed-based cleanup of the Chromium Preferences file to prevent the "restore pages?" dialog. This runs EVERY time the kiosk starts:

```bash
# Clean up Chromium crash state to prevent "restore pages?" dialog
CHROMIUM_PREFS="${USER_DATA_DIR}/Default/Preferences"
if [ -f "$CHROMIUM_PREFS" ]; then
  sed -i 's/"exited_cleanly":false/"exited_cleanly":true/' "$CHROMIUM_PREFS"
  sed -i 's/"exit_type":"Crashed"/"exit_type":"Normal"/' "$CHROMIUM_PREFS"
fi
```

Also add `--disable-restore-session-state` flag (already present) as defense-in-depth. The `--disable-session-crashed-bubble` flag is already present.

**3. Restart loop for crash recovery (BRW-02):**
Wrap the chromium-browser launch in a `while true` loop with a 5-second sleep between restarts. This is the research-recommended approach: "Keep autostart for initial Chromium launch, but wrap kiosk.sh in a restart loop."

The structure should be:
```bash
while true; do
  # Clean Chromium preferences (sed commands above)

  # Launch Chromium (existing command with new flags)
  chromium-browser \
    --kiosk \
    ... (all flags) ...
    "$DASHBOARD_URL"

  # If Chromium exits (crash or otherwise), log and restart
  log_message "Chromium exited, restarting in 5 seconds..."
  sleep 5
done
```

Add a `log_message()` function following the project convention (logger -t + echo). Use LOG_TAG from cfg_get with default "kiosk".

Keep all existing functionality: DISPLAY export, desktop load wait, unclutter, onboard, xset commands. These should run ONCE before the while loop (not inside it).

The one-time setup (unclutter, onboard, xset) goes before the loop. The Preferences cleanup + Chromium launch goes inside the loop.

<task type="auto">
  <name>Task 2: Create browser watchdog for idle auto-return and WiFi recovery reload</name>
  <files>watchdog/browser-watchdog.sh</files>
  <action>
Create `watchdog/browser-watchdog.sh` following project conventions. This is a long-running daemon that:

1. Monitors X11 idle time via `xprintidle`
2. Reloads browser to home URL after configurable inactivity timeout (BRW-03)
3. Reloads browser when WiFi recovery signal is detected (NET-05)

Script structure:
1. Shebang `#!/bin/bash` with `set -euo pipefail`
2. SCRIPT_DIR/REPO_ROOT derivation pattern
3. `source "$REPO_ROOT/lib/config.sh"`
4. Load config:
   - `INACTIVITY_TIMEOUT` from cfg_get '.browser.inactivity_timeout_seconds' with default 600
   - `DASHBOARD_URL` from cfg_require '.dashboard.url'
   - `LOG_TAG` from cfg_get with default "browser-watchdog"
5. Calculate `IDLE_TIMEOUT_MS=$((INACTIVITY_TIMEOUT * 1000))`
6. `log_message()` function (logger -t + echo)
7. `WIFI_RECOVERY_SIGNAL="/tmp/wifi-recovered"` (signal file touched by wifi-watchdog.sh after successful recovery)
8. Log startup message with configured timeout value

Main loop (`while true`):
```bash
while true; do
  # Check WiFi recovery signal
  if [ -f "$WIFI_RECOVERY_SIGNAL" ]; then
    log_message "WiFi recovery detected, reloading dashboard"
    rm -f "$WIFI_RECOVERY_SIGNAL"
    DISPLAY=:0 xdotool key F5
    sleep 10  # Brief pause after reload
    continue
  fi

  # Check idle time
  IDLE_MS=$(DISPLAY=:0 xprintidle 2>/dev/null || echo "0")
  if [ "$IDLE_MS" -gt "$IDLE_TIMEOUT_MS" ]; then
    log_message "Idle timeout reached (${IDLE_MS}ms > ${IDLE_TIMEOUT_MS}ms), reloading dashboard"
    DISPLAY=:0 xdotool key F5
    # Wait full timeout before checking again to avoid rapid-fire reloads
    sleep "$INACTIVITY_TIMEOUT"
  fi
  sleep 10  # Check every 10 seconds
done
```

For the idle auto-return, use `xdotool key F5` (page reload). Per research: "F5 reloads the current page. Since the kiosk always starts at the dashboard URL, a reload (F5) effectively returns to the home page since HA dashboards typically reset to their default view on reload."

If this doesn't work well on hardware (user navigated to sub-page that persists across reload), the user can report it and we can switch to xdotool key ctrl+l URL typing approach in a gap closure plan.

Mark script executable.
