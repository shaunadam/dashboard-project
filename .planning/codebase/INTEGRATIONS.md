## Messaging & Command Control

**MQTT Broker:**
- Provider: Home Assistant (embedded or separate)
- Connection: Configured in `config/mqtt.json` (generated by `scripts/setup/bootstrap.sh`)
- Protocol: MQTT v3.1.1
- Default Port: 1883
- Authentication: Username/password (prompted during bootstrap)
- TLS: Not configured in default setup

**MQTT Topics:**

*Command Topic (Inbound):*
- Topic: `dashboard/display/command`
- Subscriber: `scripts/mqtt_listener.py`
- Accepted payloads: `on`, `off`, `status`
- Source: Home Assistant automations

*Status Topic (Outbound):*
- Topic: `dashboard/display/status`
- Publisher: `scripts/mqtt_listener.py`
- Payloads: `on`, `off`, `unknown`
- Consumer: Home Assistant sensors and automations

*Availability Topic (Outbound):*
- Topic: `dashboard/display/availability`
- Publisher: `scripts/mqtt_listener.py`
- Payloads: `online`, `offline`
- Consumer: Home Assistant availability tracking
- Feature: Last Will and Testament configured for offline notification on disconnect

**MQTT Client Library:**
- Package: `paho-mqtt` (Python)
- Implementation: `scripts/mqtt_listener.py`
- Connection Management: Auto-reconnect on network issues
- QoS Level: 1 (at least once delivery)
- Session: Clean session disabled (persistent subscriptions)

## Data Storage

**Configuration Storage:**
- Type: Local filesystem JSON files
- MQTT Config: `config/mqtt.json` (created by bootstrap.sh from template)
- File permissions: `600` (user-only read/write)

**Display State:**
- Storage: In-memory (MQTT listener process)
- Persistence: Published to MQTT for Home Assistant tracking
- Recovery: Status queried on reconnect via `status` command

**Logs:**
- System Logs: systemd journal
  - Access: `journalctl -u [service-name] -f`
  - Services: `touchscreen-check.service`, `mqtt-listener.service`
- Python Logs: MQTT listener
  - Output: systemd journal (via StandardOutput=journal)
  - Level: INFO (configurable in `scripts/mqtt_listener.py`)

## Home Assistant Integration Points

**Automation Examples (from readme.md):**

Motion Detection Trigger:
```yaml
automation:
  - alias: "Dashboard Display On - Motion Detected"
    trigger:
      - platform: state
        entity_id: binary_sensor.living_room_motion
        to: "on"
    action:
      - service: mqtt.publish
        data:
          topic: "dashboard/display/command"
          payload: "on"
```

Scheduled Control:
```yaml
automation:
  - alias: "Dashboard Display Off - Bedtime"
    trigger:
      - platform: time
        at: "22:00:00"
    action:
      - service: mqtt.publish
        data:
          topic: "dashboard/display/command"
          payload: "off"
```

Availability Sensor:
```yaml
mqtt:
  sensor:
    - name: "Dashboard Display Status"
      state_topic: "dashboard/display/status"
      availability_topic: "dashboard/display/availability"
      payload_available: "online"
      payload_not_available: "offline"
      icon: mdi:monitor
```
